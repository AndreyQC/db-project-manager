## What this project is

`db-project-manager` (Python 3.13+, uv, typer CLI + PySide6 GUI): reverse-
engineering PostgreSQL/Greenplum DB structure into a tree of SQL files, building a
dependency graph, validation deploy into a temp DB, and (new in Phase 9) comparing
two DB states (live DB or codebase directory) with a structured diff report.

## Implemented features (by phase)

- **P1**: reverse-engineering + GUI (encrypted connections, SQL preview).
- **P2**: dependency graph + validation deploy.
- **P3**: SSH tunnel.
- **P4**: overloaded function/procedure identity (signature hash).
- **P5**: extensions, DB settings, qualify-refs post-processor.
- **P6**: function-call edges, extension filtering.
- **P7**: GUI action panel (declarative registry, 3 actions).
- **P9**: **compare** — `db-pm compare run`: diff two DB states (live or codebase),
  sqlglot-normalized SQL hashes, db_type compatibility check, JSON report.

## Key decisions & constraints

- **db_type compatibility**: compare only runs PG↔PG or GP↔GP; hard error otherwise.
  db_type stored in `dbpm.manifest.json` written by reverse-engineer.
- **sqlglot~=27.0.0**: SQL normalization via `parse_one().sql(normalize=True)`.
  Regex fallback on parse errors (lesson §44).
- **`--keep-model-dir`**: reverse-engineer of a DB side goes to a temp dir, cleaned
  in `finally`; flag preserves it for audit (analogous to `--keep-db`).
