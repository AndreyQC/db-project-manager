## What this project is

`db-pm` — CLI + GUI tool (Python 3.13+, PySide6, PostgreSQL/psycopg2) that
reverse-engineers a live DB into a graph of objects, generates idempotent DDL
migration scripts, and deploys them. Phase 6 adds a post-processor that
qualifies bare object references in generated SQL so deploys succeed regardless
of `search_path` on the target database.

## Key design decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Parser | Regex + tokenizer | No new deps; covers ~95% of cases (function calls, FROM/JOIN). AST via sqlglot is BACKLOG P3+. |
| Trigger | Both auto (after reverse) and manual CLI | Auto gives zero-config; manual allows re-run / dry-run inspection |
| Ambiguous names | Skip + log in report | Tool can't guess schema; user must resolve manually |
| Reserved keywords | Skip (lowercased set) | `count`, `now`, etc. are built-ins, not user objects |
| Self-references | Skip | A function calling itself is fine as-is |
| Error policy in reverse | Swallow qualify errors | Post-processor is best-effort; never fails reverse-engineer |
| Dry-run | Report always written, files untouched | User can inspect what WOULD change before committing |
