## What this project is

`db-pm` — CLI + GUI tool (Python 3.13+, PySide6, PostgreSQL/psycopg2) that
reverse-engineers a live DB into a graph of objects, generates idempotent DDL
migration scripts, and deploys them. Phase 4 fixes identification of overloaded
functions/procedures (PostgreSQL permits same name with different arg types).

## Key design decision (diverged from plan, kept as invariant)

**`object_key` always carries `/signature/<hash>` for functions/procedures with args
— regardless of whether overload siblings exist.** The original plan proposed adding
the suffix only on collision; implementation chose the deterministic variant:

| Layer | Suffix rule | Why |
|-------|-------------|-----|
| `object_key` | Always when signature non-empty | Pure function of identity — same key on any DB |
| File name | Only on overload collision | Keeps singleton files short (`function sp_y.sql`) |

Documented in `Phase_4_vision_final.md` §4.2 and `001_plan_phase_04.md` P4.S02.

## Key decisions & constraints

| Decision | Choice | Why |
|----------|--------|-----|
| Suffix format | SHA-256 (8 hex) | Zero collision risk; alternatives (`int4_text`, hybrid) collide on short type prefixes |
| Scope | Full (identity + file names) | Hidden bug (silent vertex overwrite) was worse than the visible long-name symptom |
| Key invariant | Deterministic from signature alone | Portable across DBs; backward-compatible for tables/views/sequences/functions-without-args |
| File name rule | Suffix only on overload collision | Short names stay readable when no overload exists |
| Alias mapping (int4↔integer) | Not implemented | `argument_types` arrives from `pg_type.typname` already normalized |
