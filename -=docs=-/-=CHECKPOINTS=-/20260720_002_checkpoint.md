## What this project is

`db-pm` — CLI + GUI tool (Python 3.13+, PySide6, PostgreSQL/psycopg2) that
reverse-engineers a live DB into a graph of objects, generates idempotent DDL
migration scripts, and deploys them. Phase 5 closes the extensions and database
settings gap that blocked real-DB usage (`citext`, `uuid-ossp`, `ALTER DATABASE SET`).

## Key design decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Extension version | Not pinned in DDL; informational in autodoc | Pinned VERSION fails on different cluster versions; `--pin-extension-versions` → future config flag |
| SET parameters | One file `settings/database settings.sql` | Q2 resolved: parameters are semantically independent; granularity later if needed |
| db_properties | Passed to `create_database`, not rendered in scripts | encoding/locale apply at DB-creation time, not per-script |
| settings script | Original DB name replaced at deploy time | Template uses source name; deploy substitutes target name |
| db_properties fields | encoding, lc_collate, lc_ctype, template only | Q8 resolved: operational fields (datconnlimit, datistemplate) excluded |
