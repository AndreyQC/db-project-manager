## Что это за проект

Python-инструмент (PostgreSQL/Greenplum) для reverse-engineering БД в дерево
SQL-файлов, построения графа зависимостей, validation deploy на пустой temp-БД,
сравнения состояний и (с Phase 10) controlled-deployment фундамента. Стек:
Python 3.13, uv, pydantic v2, typer (CLI), PySide6 (GUI), sqlglot, testcontainers.
Пакеты: `domain` → `infrastructure` → `application` → `presentation`.

## Key decisions & constraints (новое в Phase 10)

- **`__deploy` — обычная схема в кодовой базе** (CDF-10), не adapter-magic.
  Deploy требует её наличия (hard error если нет); seed делается RE из canonical
  templates. `immutable: true` в autodoc.
- **Calver `YYYY.MM.DD.NN`** в manifest, required при v2 (CDF-2/9). Git полностью
  убран из versioning — версия explicit, MR-controlled.
- **State + history разделены** (CDF-11): `script_history` PK `(name, type)`
  UPSERT (для runner lookup'а); `script_audit_log` append-only с
  `deploy_version`/`deploy_source` для отчётов Phase 13.
- **Checksum без autodoc** (CDF-6) — `script_checksum(strip_autodoc(text))`.
- **5-way runner decision** — добавлена ветка «different checksum + previous
  failure → EXECUTE» (retry с фиксом); остальные 4 из vision_final §4.4.
- **Split deploy loop** — `__deploy` schema+tables применяются ПЕРВЫМИ (до
  pre-runner, которому нужна `script_history`).
- **Domain остаётся pure** — `canonical_normalize`/`script_checksum` работают с
  уже стрипнутым текстом; caller ответственен за `strip_autodoc`. Отклонение от
  плана (там strip был внутри), зафиксировано тестом
  `test_script_checksum_invariant_under_autodoc_change`.
- **`MANIFEST_FORMAT_VERSION=2`** — старые v1-манифесты парсятся (для migration
  через RE), новые пишутся только v2.
