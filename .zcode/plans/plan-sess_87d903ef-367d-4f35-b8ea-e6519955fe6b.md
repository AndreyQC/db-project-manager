# Phase 15: GUI deploy plan/apply + Plan Viewer

> **Назначение:** закрыть BACKLOG P3 «GUI-действия deploy plan/apply + рендер плана деплоя». Phase 12 дала `deploy plan`/`apply` в CLI, Phase 14 дала Delta Viewer для `diff_report.json`; GUI-доступа к apply к живой БД пока нет — пользователь вынужден переключаться в терминал. Фаза закрывает полный GUI-флоу **analyze → plan → apply** с просмотром плана и явным подтверждением мутации.

---

## 1. Цель фазы

1. **GUI-обёртки для `deploy plan` и `deploy apply`** по образцу Phase 11 `deploy_analyze`: settings-модели, диалоги, воркеры, `build_cli_*`, регистрация в `ActionSpec`.
2. **`PlanViewerWindow`** (отдельное окно, по образцу `DeltaViewerWindow`): дерево операций плана с цветами classification, фильтры safe/needs-pre/blocked, просмотр SQL-артефактов `delta/NNN_*.sql` с подсветкой (`SqlHighlighter(diff_mode=True)`).
3. **Preflight-warning в `DeployApplyDialog`:** красный заголовок «⚠ Изменяет существующую БД» + обязательный чекбокс «Я понимаю последствия» (отдельное поле в settings).
4. **Chain analyze → plan → apply из Plan Viewer:** кнопка «Применить» открывает `DeployApplyDialog` с предзаполненными `codebase_dir`/`target_connection`/`output_dir` из последнего plan.
5. **Открытие Plan Viewer по запросу:** кнопки «Открыть план» в диалогах plan/apply после успешного выполнения (НЕ авто-открытие).
6. **Контракт-тесты GUI↔CLI и offscreen-smoke** для новых действий (уроки §39, §41–§43).
7. **Все три CLI-флага** (`--include-drops`, `--no-rehearsal`, `--keep-rehearsal-db`) доступны из GUI.

**Не входит:** авто-генератор seed (BACKLOG P3 «ALT-8b»), analyze-даунгрейд по ALT-3 (BACKLOG P3 «analyze: даунгрейд»), GUI рендер `safety_gate_report.md` (уже есть `safety_gate_report.md`-path в QMessageBox — не трогаем в этой фазе).

## 3. Ключевые решения

### PRE-1: Plan Viewer — отдельное окно
`PlanViewerWindow(QMainWindow)` — новый файл `src/db_project_manager/presentation/gui/widgets/plan_viewer.py` по образцу `delta_viewer.py`. Принимает `DeltaPlan` через `show_plan(plan, *, path)` (синхронный, для тестов) и `load_from_path(path)` (асинхронный, через новый `LoadPlanReportWorker`). Дерево: `type → schema → object`, цвета по `OperationClass`: SAFE — зелёный, NEEDS_PRE — жёлтый, BLOCKED — красный. Табы: «Детали» (object_key/object_type/action/reason/estimated_rows/covered_by) + «DDL» (содержимое `script_file` с `SqlHighlighter(diff_mode=True)`). Summary bar: «safe: X, needs-pre: Y, blocked: Z». Кнопка «Применить» в тулбаре (см. PRE-3).

### PRE-2: Apply-gate — обязательный чекбокс + красный заголовок
В `DeployApplyDialog`: верхний лейбл `QLabel` с `setStyleSheet("color: red; font-weight: bold")` и текстом «⚠ Изменяет существующую БД. Репетиция обязательна (кроме CI).», плюс `QCheckBox("Я понимаю последствия и хочу применить")`. Кнопка «OK» (`Применить`) по умолчанию `setEnabled(False)`, `setEnabled(checkbox.isChecked())` через `stateChanged`. Поле `confirm_understands_risk: bool = False` в `DeployApplySettings`. CLI-билдер игнорирует это поле (только GUI-side гейт).

### PRE-3: Chain через Plan Viewer
После успешного `deploy plan` или `deploy apply` в диалоге Plan/Apply появляется кнопка «Открыть план» (читает `<output_dir>/plan.json` через `PlanViewerWindow.load_from_path`). В `PlanViewerWindow` тулбар-кнопка «Применить» собирает `DeployApplySettings` с предзаполненными `codebase_dir`/`target_connection`/`output_dir` (из текущего `DeltaPlan` + выбранного `target_connection` — нужно сохранить в state viewer'а), открывает `DeployApplyDialog` модально. После успешного `DeployApplyDialog` — обновляет тот же viewer на новый `plan.json`.

### Не-функциональные
- **Урок §42 (signal → strong ref):** все новые воркеры следуют паттерну `WorkerSignals` + хранение `(worker, action_id, settings)` в `MainWindow._active_workers` и в самом viewer'е (`_active_workers: dict`).
- **Урок §43 (кнопки последними):** в новых диалогах `_add_buttons()` вызывается последней строкой `__init__`.
- **Урок §40 (имя `validate`):** в settings используем `codebase_dir`/`target_connection`/`output_dir` (уже есть в `DeployAnalyzeSettings` — переиспользуем имя).
- **Урок §39 (shlex):** helper `_argv` остаётся в `tests/unit/test_action_cli.py`; `build_cli_*` используют `shlex`-совместимые пути.
- **Урок §41 (offscreen smoke):** новые тесты в `tests/unit/test_action_panel_smoke.py` — offscreen, `QT_QPA_PLATFORM=offscreen`, `qapp` scope=module.
- **Урок §47 (combo index):** `_connections_combo` уже возвращает `userData=name` — `findData` где нужно; никаких хардкод-индексов.

## 5. Шаги реализации (S1..S5)

### S1 — settings + CLI-builders + реестр
- `models.py`: добавить `DeployApplySettings` (новый, НЕ переиспользовать `DeployAnalyzeSettings` — у apply три дополнительных флага + preflight).
- `cli.py`: `build_cli_deploy_plan`, `build_cli_deploy_apply` (по образцу `build_cli_deploy_analyze`, добавить флаги).
- `registry.py`: импорты + два `ActionSpec` (`deploy_plan`, `deploy_apply`) с `required_fields=("codebase_dir", "target_connection", "output_dir")`. Фабрики `make_dialog/make_worker` — заглушки, которые пока поднимают `NotImplementedError` (заменятся в S2).

**Проверки:** unit-тесты на settings-валидацию; `ruff check`; `pytest tests/unit/test_action_cli.py -q` — контрактные тесты с mock'ами `_load_connection` и сервисов (можно использовать существующий `_patch_common`).

### S2 — диалоги + воркеры
- `dialogs.py`: `DeployPlanDialog`, `DeployApplyDialog` (последний — с preflight по PRE-2; `_add_buttons()` последним, урок §43).
- `workers.py`: `DeployPlanWorker`, `DeployApplyWorker` (по образцу `DeployAnalyzeWorker`, следуя уроку §42). `DeployApplyWorker.run` вызывает `DeployApplyService(...).apply(...)`; при `DeployApplyRejected` и `DeployApplyError` — `signals.error.emit(...)` + `signals.finished.emit(None)`. При успехе — `signals.finished.emit(apply_result)`.
- `registry.py`: заменить заглушки фабрик на реальные `_make_deploy_plan_dialog`, `_make_deploy_apply_worker`, привязать `build_cli_*`.

**Проверки:** offscreen-smoke в `test_action_panel_smoke.py` — конструктор диалога + `_last_form_widget is QDialogButtonBox`; `test_apply_dialog_confirm_checkbox_gates_ok` — `OK.isEnabled() == False` по умолчанию, `True` после `setChecked(True)`.

### S3 — Plan Viewer
- `widgets/plan_viewer.py` (новый): `PlanViewerWindow` по образцу `DeltaViewerWindow`. Импорт: `DeltaPlan` из `domain/delta`, `OperationClass` для цветов, `load_plan_report` — новая функция в `infrastructure/deploy/plan_report.py` (`def load_plan_report(path) -> DeltaPlan: return DeltaPlan.model_validate_json(Path(path).read_text(encoding="utf-8"))`) — симметрично с `DeltaReport.model_validate_json` в `LoadDiffReportWorker`.
- `workers.py`: `LoadPlanReportWorker(path) -> DeltaPlan` (по образцу `LoadDiffReportWorker`).
- `_CLASSIFICATION_COLORS: dict[OperationClass, str]` — зелёный/жёлтый/красный.
- Дерево: `type → schema → object`. При выборе листа — табы «Детали» (`object_key`, `object_type`, `object_name`, `action`, `classification`, `reason`, `estimated_rows`, `covered_by`, `script_file`) + «DDL» (`Path(plan_viewer_dir).parent / script_file` если файл существует — `SqlHighlighter(document, diff_mode=True)`). Summary bar: «safe: X, needs-pre: Y, blocked: Z».
- Тулбар: «Открыть JSON…» (QFileDialog, фильтр `*.json`, проверка что это `DeltaPlan` через `DeltaPlan.model_validate_json`), «Применить» (см. PRE-3, задизейблена пока нечего применять — после S4).

**Проверки:** `test_plan_viewer.py` — offscreen-смоук: создать фикстуру `DeltaPlan` (3 операции разных classification), `show_plan(plan)`, проверить дерево, фильтры, рендер DDL.

### S4 — связка analyze → plan → apply
- `main_window.py`: добавить `open_plan_viewer(report_path=None)` (по образцу `open_delta_viewer`). В `_on_action_finished` ветка `deploy_apply` → `_report_apply_result(apply_result, settings)`: показывает QMessageBox с `applied/planned/applied_version` + кнопка-предложение «Открыть план» (открывает `PlanViewerWindow.load_from_path(output_dir / "plan.json")`). Аналогично для `deploy_plan`.
- `PlanViewerWindow`: состояние `_last_target_connection: str | None`, `_last_codebase_dir: str | None`, `_last_output_dir: str | None`. Кнопка «Применить» в тулбаре открывает `DeployApplyDialog` с предзаполненными полями (модально поверх viewer'а). После успешного `DeployApplyWorker` — `self.load_from_path(<новый plan.json>)` (обновить тот же viewer).
- `PlanViewerWindow`: пункт меню «Вид → Plan Viewer…» в `main_window.py:115-151` (по образцу Delta Viewer).

**Проверки:** integration-тест `test_deploy_plan_apply_gui_e2e.py` (testcontainers) — сценарий «analyze → plan → open Plan Viewer → apply (после preflight-чекбокса) → verify `applied_version` + артефакты»; offscreen-smoke `_on_plan_viewer_apply_btn` — мок `DeployApplyDialog` через monkeypatch, проверить, что viewer получает новый `plan.json` (без реальной БД).
