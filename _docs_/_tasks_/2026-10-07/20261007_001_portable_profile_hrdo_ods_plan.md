## Цель

Не пересобирать бандл, а подготовить инструкцию и готовые файлы так, чтобы
уже собранный `dbpm-portable/` можно было запустить на другой машине и
выполнить профайлинг всех таблиц подключения `hrdo_ods` (маскированные
ODS-данные, бэкап от 2026-10-06).

Код приложения не меняется — задача только про файлы запуска и инструкцию.

## Факты

- Подключение: `IVSD00258.reksoft.com_PG__DB__hrdo_ods__U_postgres`
  (PG 5432, user `postgres`, пароль — токен `crypto__ENVOS_CRYPTO_01__...`).
- Схемы для профайлинга (из комментария в yaml): `ods_hn_zup_masked`,
  `ods_hn_trade_zup_masked`. Таблицы в mixed-case — идентификаторы только
  в двойных кавычках.
- Блок `profiling:` в yaml: `enabled: true`, порог сэмпла 1 ГБ,
  `sample_rows: 100000`, `statement_timeout_ms: 120000`.
- Список таблиц снят с этой машины 2026-10-07 (read-only запрос к
  `information_schema.tables`): **119 таблиц** — 62 в
  `ods_hn_trade_zup_masked`, 57 в `ods_hn_zup_masked`.
- Бандл `dbpm-portable/` собран и в его `connections/` нового файла
  `hrdo_ods` ещё нет (лежит только старый `..._DB__hrdo_ods.yaml`).
- CLI: `db-pm profile <имя> --tables "schema"."Table",...` — список таблиц
  передаётся явно; команды «все таблицы схемы» нет. Имя подключения =
  имя файла без `.yaml`.

## Решения (согласованы с пользователем)

1. **Запуск на другой машине** — бандл копируется целиком; целевая машина
   должна видеть `IVSD00258.reksoft.com:5432`. env-ключа там нет.
2. **Пароль — интерактивный ввод**: токен в yaml остаётся как есть; при
   отсутствии env-ключа CLI сам запросит пароль скрытым вводом (фича
   коммита `7cac922`). Пароль пользователя `postgres` нужно знать на
   целевой машине.
3. **Список таблиц вшит в файл запуска** (не собирается на целевой машине):
   данные — статичный бэкап, список снят заранее.
4. **Форма запуска — python-обёртка в корне бандла, а не длинный
   `--tables` в .cmd.** Причины: строка на 119 квотированных имён —
   ~8 КБ, упирается в лимит cmd.exe 8191 символ; экранирование кавычек
   (`\"...\"`) в cmd хрупко; обёртка в одном процессе = один ввод пароля
   на все 119 таблиц (в CLI-пути кэш пароля живёт только внутри процесса).
   Обёртка переиспользует CLI-команду `profile()` (та же запись отчётов),
   отчёты пишет в `reports/` рядом с бандлом независимо от CWD.

## Что готовим (deliverables)

| Файл (копия в `files/`, живьём — в корне бандла) | Назначение |
|---|---|
| `profile_hrdo_ods.py` | обёртка: bootstrap как `dbpm_cli.py`, вшитый список 119 таблиц, вызов CLI `profile()` |
| `dbpm_profile_hrdo.cmd` | запуск обёртки встроенным python бандла |
| `PROFILE-HRDO-ODS.md` | инструкция для целевой машины (шаги, пароль, сбор отчётов) |
| — | копия исправленного yaml в `dbpm-portable/connections/` (в git не попадает: `connections/` вне git, токен секретен) |

Путь до подключений в обёртке — `<бандл>\connections`, отчёты —
`<бандл>\reports\<имя подключения>\<schema>.<table>.json`.

## Шаги

1. Файлы в `_tasks_/2026-10-07/files/` (контрольные копии для git).
2. Копирование в `dbpm-portable/`: обёртка, .cmd, инструкция в корень;
   yaml — в `connections/`.
3. Smoke на этой машине (env-ключ есть, prompt не сработает):
   а) `dbpm.cmd profile <имя> --tables "\"ods_hn_zup_masked\".\"Region\""`
   — проверка runtime бандла, крипто, подключения, парсера квотированных
   имён, записи отчёта;
   б) обёртка с подменённым списком из одной таблицы (импорт модуля,
   `TABLES=[...]`, вызов `main()`) — проверка всей цепочки запуска.
4. Полный прогон 119 таблиц — на целевой машине пользователем.

## Приёмка

- Smoke-отчёт JSON создан в `dbpm-portable/reports/...`, ключевые поля
  заполнены (schema/table/size/columns).
- `uv run pytest` и `ruff check .` не затронуты (код приложения не менялся).
- Инструкция самодостаточна: шаги от копирования бандла до возврата
  `reports/`, без ссылок на чат.

## Риски / ограничения

- Целевая машина должна иметь сетевой доступ до `IVSD00258.reksoft.com:5432`
  (проверка — `dbpm.cmd profile` на одну таблицу из инструкции).
- Длительность полного прогона неизвестна (119 таблиц; таблицы >1 ГБ пойдут
  по сэмплу; на каждый запрос statement_timeout 120 с).
- Отчёты содержат агрегаты маскированных данных — хранить/передавать
  осознанно (`reports/` в git не попадает и в бандле не нужен в общих местах).
- Повторный запуск перезаписывает JSON-профили (идемпотентно, read-only).
