# Профайлинг hrdo_ods через portable-бандл — инструкция

Профайлинг всех таблиц БД `hrdo_ods` (маскированные ODS-данные, бэкап
от 2026-10-06) через уже собранный портативный пакет `dbpm-portable`.
Устанавливать ничего не нужно: Python и зависимости уже внутри бандла,
интернет не требуется.

## Что профилируется

- Подключение: `IVSD00258.reksoft.com:5432`, БД `hrdo_ods`, пользователь
  `postgres` (файл `connections\IVSD00258.reksoft.com_PG__DB__hrdo_ods__U_postgres.yaml`).
- Схемы: `ods_hn_zup_masked` и `ods_hn_trade_zup_masked`. Обёртка сама
  снимает список таблиц этих схем из `information_schema` при каждом
  запуске (на момент задачи — 119 таблиц); вшитого списка таблиц нет.
  Чтобы прогнать **другие схемы**, впиши их имена в `SCHEMAS` в
  `profile_hrdo_ods.py` (перед быстрой проверкой удобно поставить
  `LIMIT = 3` в том же файле).
- Имена таблиц в mixed-case (`"Region"`, `"Status_data_employees"`) —
  обёртка квотирует их автоматически; вручную их тоже надо писать
  в кавычках, иначе PostgreSQL свернёт имя в нижний регистр и не найдёт.
- Профайлинг read-only: только SELECT-агрегаты (перцентили, гистограммы,
  top-N, nulls/distinct). ANALYZE не запускается, данные не меняются.
- Таблицы крупнее 1 ГБ (`pg_total_relation_size`) считаются по сэмплу
  100 000 строк (настройки в блоке `profiling:` yaml-файла подключения);
  на каждый запрос установлен таймаут 120 секунд.
- JSON-профиль записывается сразу после профильирования таблицы: сбой на
  одной таблице (или обрыв сети) не теряет результаты остальных.

## Что нужно на целевой машине

1. Папка `dbpm-portable` целиком (сеть/флешка/RDP) — со всеми добавленными
   файлами: `profile_hrdo_ods.py`, `dbpm_profile_hrdo.cmd`,
   `PROFILE-HRDO-ODS.md` и обновлённым
   `connections\IVSD00258.reksoft.com_PG__DB__hrdo_ods__U_postgres.yaml`.
2. Сетевой доступ до `IVSD00258.reksoft.com`, порт `5432`.
3. Пароль пользователя `postgres` от этой БД — ввести один раз по запросу
   (скрытый ввод; env-ключ шифрования не нужен).

## Запуск

Открыть cmd **в папке бандла** — двойным кликом по `terminal.cmd`
(откроет консоль уже в папке бандла) или вручную — и выполнить:

```bat
dbpm_profile_hrdo.cmd
```

Дальше:

1. На запрос `! env-ключ ENVOS_CRYPTO_01 недоступен ...` ввести пароль
   подключения (ввод скрыт).
2. Дождаться окончания: по каждой таблице печатается строка `OK ...` (или
   `ОШИБКА ...` — тогда таблица будет в итоговом списке неудачных), всего
   119. Пустые таблицы помечаются предупреждением о статистике — это
   нормально. В конце печатается `Готово: N/119`; если были неудачи,
   код возврата 1 и список таблиц для точечного перезапуска.
3. Профили появляются в папке (рядом с бандлом) по мере работы:

   ```
   reports\IVSD00258.reksoft.com_PG__DB__hrdo_ods__U_postgres\
     ods_hn_zup_masked.Account_groups.json
     ods_hn_trade_zup_masked.Region.json
     ...
   ```

4. Скопировать папку `reports\IVSD00258.reksoft.com_PG__DB__hrdo_ods__U_postgres`
   обратно (119 JSON-файлов, один на таблицу).

Повторный запуск безопасен: ничего в БД не меняется, JSON-профили
перезаписываются.

## Проверка одной таблицы (опционально, до полного прогона)

```bat
dbpm.cmd profile IVSD00258.reksoft.com_PG__DB__hrdo_ods__U_postgres --tables "\"ods_hn_zup_masked\".\"Region\""
```

`\"` внутри — экранирование кавычек для cmd; сам db-pm получит имя
`"ods_hn_zup_masked"."Region"`. Отчёт ляжет в тот же `reports\...`.

## Если что-то не так

- **Зависает на подключении / «connection refused»** — нет сети до
  `IVSD00258.reksoft.com:5432` с целевой машины (VPN? файрвол?).
- **«password authentication failed»** — опечатка в пароле `postgres`;
  запустить команду заново.
- **«таблица не найдена» (relation does not exist)** при ручном запуске —
  имя без двойных кавычек или схема/таблица не из списка выше.
- **«profiling disabled»** — в yaml подключения нет блока
  `profiling: enabled: true` (в приложенном yaml он есть).
- **Обрыв сети посреди прогона** — нажмите Ctrl+C: готовые JSON уже
  сохранены; после восстановления сети запустите `dbpm_profile_hrdo.cmd`
  снова (готовые профили перезапишутся, остальные досчитаются).
- **Ошибка на отдельной таблице** (необычный тип колонки и т.п.) не
  останавливает остальные — в конце будет список неудачных; каждую можно
  перегнать точечно командой из раздела «Проверка одной таблицы»,
  подставив её имя.
