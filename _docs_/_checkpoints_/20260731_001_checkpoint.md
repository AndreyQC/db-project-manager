## Что это за проект

Python-инструмент (PostgreSQL/Greenplum) для reverse-engineering БД в дерево SQL-файлов,
построения графа зависимостей, validation deploy на пустой temp-БД и сравнения состояний.
Стек: Python 3.13, uv, pydantic v2, typer (CLI), PySide6 (GUI), sqlglot, testcontainers.
Пакеты: `domain` → `infrastructure` → `application` → `presentation`.

## Key decisions & constraints (новое в Phase 8)

- **Inference консервативен:** только литералы; всё прочее → unresolved + fallback-first.
  Никогда не угадывает (принцип безопасности, LESSONS §36).
- **int-литерал → int4** (PG default); если перегрузки только int2/int8 → unresolved.
- **Routing по raw SQL**, не по word-потоку (скобки сносятся нормализатором).
- **`_mask_noncode`** бланкует строки/комментарии для поиска вызова, но тело аргументов
  срезается из оригинала (чтобы строковые литералы-аргументы доходили до inference).
- **Определения ≠ вызовы:** `CREATE FUNCTION/PROCEDURE name(...)` пропускается в find_calls.
- **Контракт `parse_directory → DependencyGraph` не сломан** (урок §18): notes в атрибуте
  парсера; отчёт пишет сервис.
- **`build:false`** в autodoc исключает объект из деплоя через `filter_build_true` — цепочка
  CLI/GUI → `deploy_order(build_only=True)` не обходится. Регрессионного теста пока нет.
