## Что это за проект

Python 3.13 инструмент для PostgreSQL/Greenplum: reverse-engineering БД → дерево SQL-файлов,
граф зависимостей, validation deploy на temp-БД, сравнение состояний,
controlled-deployment с safety-gate и репетицией, GUI на PySide6. Стек: `uv`,
pydantic v2, typer (CLI), PySide6 (GUI), sqlglot, testcontainers. Пакеты:
`domain → infrastructure → application → presentation`.

## Delta относительно 20260902_001

Закрыт критический баг cis_zup feedback 2026-09-02: `deploy apply` на пустую
target-БД падал с `psycopg2.errors.InvalidSchemaName` на первой таблице.
Root cause — `infrastructure/diff/snapshot.py::DIFFED_TYPES` не содержал
`"schema"`, из-за чего `CompareService` терял 7 schema vertices при построении
snapshot; в `plan.json` не было CREATE SCHEMA операций; deploy выполнял
только CREATE TABLE для таблиц в несуществующих схемах.

Также проверена консистентность RE ↔ yaml apply для `__deploy/schema __deploy.sql`:
оба используют единую функцию `seed_deploy_files` (canonical_ddl.py) — разница
только в `overwrite` (RE: True, yaml apply: False).

## Key decisions & constraints (новое в Phase 15.5)

- **`DIFFED_TYPES` включает `"schema"`** (Phase 15.5 fix). Без этого
  `CompareService` терял schema vertices, deploy apply на пустой target-БД
  не работал. Регрессия зафиксирована тестом `test_snapshot_includes_schema_vertices`.
- **`schema`-level diff теперь видим** — ALTER SCHEMA OWNER, GRANT USAGE,
  default privileges на схемах теперь дают CHANGED entries (цена > пользы
  от подавления шума; см. LESSONS §61).
- **RE vs yaml apply консистентность** (новое в Phase 15.5 review):
  оба через `seed_deploy_files` (canonical_ddl.py), разница только в
  `overwrite` (RE=True, yaml apply=False).
