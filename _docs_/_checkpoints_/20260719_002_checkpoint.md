## What changed since 20260719_001

### Bugfixes found during Deploy Validate on dagster DB

**dagster DB** (`D:\tune-db-manager\local-pg-db-dagster\dagster`) — real-world
PostgreSQL database with reserved-word column names (`limit`, `user`, etc.)

Three bugs found and fixed:

| Bug | Symptom | Root cause | Fix |
|-----|---------|-----------|-----|
| A | `int8(64, 0)` — syntax error on bigint columns | `type_mod()` appended `(precision, scale)` to all types | `_NO_NUMERIC_MOD` frozenset — skip for int/float/time types |
| B | `CONSTRAINT asset_check_executions_id_not_null NOT NULL id` | NOT NULL CHECK-constraints from `information_schema` leaked into DDL | Filter in `_build_table()` — `nullable` already set via `col[2]=='YES'` |
| C | `limit int4 NOT NULL` — syntax error on reserved word column | Identifiers not quoted in SQL templates | `_qi()` helper — all identifiers in all 9 templates now double-quoted |

### New files

```
postgres/keywords.yaml   — PG 18 reserved words (from official docs)
postgres/keywords.py    — loader: get_reserved()
```

Design note: `_qi()` always quotes (DBMS-neutral, SQL standard). The
`reserved_keywords` set is included in `structure` dict for future explicit
use (linting, etc.) but is not required for quoting.
