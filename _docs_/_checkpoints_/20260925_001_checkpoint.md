## Что сделано (сессия 2026-09-25, задача 20260925_001)

Hotfix Phase 18: `deploy reset` падал на GP-таргете при content-drop —
routine-DROP рендерились без списка аргументов, а ядра < PG 10 (GP 6 = 9.4)
требуют `name(arg_list)` даже пустым. Две итерации диагностики: гипотеза
«CASCADE нелегален на ядрах < 13» опровергнута живым прогоном (ошибка
сместилась с `CASCADE` на `;`), корневая причина — `if args:` выкидывало
скобки для zero-arg routines (`pg_get_function_identity_arguments` → `''`).

| Concern | Path | Note |
|---------|------|------|
| Фикс | `postgres/adapter.py::drop_schema_contents` | routines всегда с `(args)`/`()`, CASCADE возвращён; версионный гейт (вводился по гипотезе 1) удалён |
| Тесты | `tests/unit/test_pg_adapter_routine_drop_args.py` | +3 net; итог 1063 unit passed, ruff чист |
| Доки | `_tasks_/2026-09-25/20260925_001_gp6_routine_drop_parens_{plan,result}.md`, `LESSONS_LEARNED.md` §74 | хронология гипотез + уроки |

## Ключевые решения сессии

- D1: пустой identity-рендер (`''`) ≠ «опустить клаузу» — в DDL с позиционным
  списком аргументов пустой список всё равно рендерится (`name()`).
- D2: CASCADE для routines сохранён — со скобками легален на любом ядре;
  закрывает и случай aggregate↔support-функция.
- D3: код на опровергнутой гипотезе не оставляем (гейт по server_version_num
  откачен полностью).
- Урок диагностики (§74-1): «syntax error at or near X» — токен-позиция
  парсера, не причина; смещение X после правки = причина не тронута.
