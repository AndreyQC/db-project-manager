## Что реализовано

### S17 — Domain Model ✅
- `ConnectionType` enum: `DIRECT`, `SSH_TUNNEL`
- `SSH_TunnelConfig` pydantic model с полями: `ssh_host`, `ssh_port`, `ssh_user`, `ssh_pass`, `remote_bind_host`, `remote_bind_port`, `local_bind_port`
- `ConnectionConfig` расширен с `connection_type` и `ssh_tunnel`
- Валидация: `SSH_TUNNEL` требует `ssh_tunnel` block

### S18 — SSH Tunnel Manager ✅
- `SSHTunnelManager` class (paramiko-based, НЕ sshtunnel из-за совместимости с paramiko 5.x)
- Lifecycle: `start()` → `stop()`
- Password authentication
- Timeout 10 сек на TCP connect
- Логирование через loguru

### S19 — PostgresAdapter via Tunnel ✅
- `connect()` диспетчеризует по `connection_type`
- `_connect_direct()` — оригинальная логика
- `_connect_via_ssh_tunnel()` — SSH tunnel + PG connection
- `disconnect()` корректно закрывает туннель

### S20 — GUI + Integration ✅
- Connection Type dropdown: `Direct PG` / `SSH Tunnel PG`
- SSH поля появляются только при выборе SSH Tunnel
- Eye-toggle для SSH passphrase
- SSH passphrase маскируется `***` при загрузке, оригинал сохраняется
- `connections/example.yaml` обновлён

### ConnectionStore — Encryption ✅
- `save()` шифрует: DB password + SSH (`ssh_host`, `ssh_user`, `ssh_pass`)
- `get_decrypted_nested_dict()` расшифровывает рекурсивно

## Проблема: Зависание при подключении к PG через туннель

**Симптом:** Туннель поднимается успешно (лог показывает "SSH tunnel ready on port N"), но PG подключение зависает.

**Последние логи (до зависания):**
```
SSH tunnel: starting connection to 217.198.9.150:22
SSH password is plaintext
Creating tunnel manager...
Starting tunnel (this may take up to 10 seconds)...
SSH connecting to 217.198.9.150:22 as root
Calling SSH client connect...
SSH transport acquired
SSH tunnel ready on port 60313
```

**Логов после этого нет — зависание в _accept_loop или _pipe.**

### Возможные причины:
1. `_accept_loop` не получает соединение от PG клиента
2. Канал открыт но данные не передаются
3. paramiko 5.x изменил API для port forwarding

### Что проверить:
1. Работает ли port forwarding с `SSHClient.get_channel().send/recv`
2. Правильно ли передаётся `client_sock.getpeername()` в `open_channel`
3. Нужно ли использовать `SSHClient.invoke_shell()` или другой механизм
