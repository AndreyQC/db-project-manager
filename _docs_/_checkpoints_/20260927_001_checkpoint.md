## Что сделано (сессия 2026-09-27, задача 20260927_001)

Локальный MCP-сервер `db-pm-mcp` (stdio, официальный MCP SDK / FastMCP —
sync-инструменты в thread-executor) поверх существующих подключений.
Пользовательские требования: (1) контракт готов к другим СУБД (capability-
флаги, диалект-агностичные модели), (2) все настройки MCP — в файлах
подключений (блок `mcp:`), (3) read-only по умолчанию + opt-in запись,
(4) полный набор инструментов включая деплой. Референс — crystaldba/
postgres-mcp (двухслойный read-only, запрет ANALYZE для write, denylist
функций, гранулярная инспекция, ToolAnnotations).

12 инструментов: list_connections, list_schemas, list_objects,
get_object_details, query, explain, get_top_queries, run_script,
deploy_plan, deploy_analyze, deploy_apply, deploy_reset.

| Concern | Path | Note |
|---------|------|------|
| Домен | `domain/query.py`, `domain/connection.py` | QueryResult/ExplainResult; McpSettings (блок mcp:) |

## Ключевые решения

- RO-backstop: `BEGIN TRANSACTION READ ONLY … ROLLBACK` на connection из
  engine pool (не общий self._connection) — таймаут/RO не протекают в
  деплой-операции.
- EXPLAIN всегда в RO-транзакции (ANALYZE write-стейтмента блокирует сервер).
- Политика: query/explain/инспекция — всегда; run_script ← `mcp.allow_writes`
  (+confirm_destructive для DROP/TRUNCATE/UNKNOWN); deploy_apply/reset ←
  `mcp.allow_deploy` + штатные предохранители (rehearsal, SafetyGate,
  allow_drop_schemas, confirm_database).
- Деплой-инструменты повторяют CLI-проводку (create_run_dir, progress →
  последние 50 строк ответа) — обход невозможен.
