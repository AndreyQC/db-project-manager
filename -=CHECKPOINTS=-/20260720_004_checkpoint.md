## What this project is

`db-pm` — CLI + GUI tool (Python 3.13+, PySide6, PostgreSQL/psycopg2) that
reverse-engineers a live DB into a graph of objects, generates idempotent DDL
migration scripts, and deploys them. Phase 6 closed the gap of bare object
references in generated SQL; subsequent hotfixes came from running the tool
end-to-end against a real production-like DB (`qr_pamyat`, 363 SQL files).

## Key design decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Qualify-refs parser | Regex + tokenizer | No new deps; covers ~95% of cases. AST via sqlglot is BACKLOG P3+. |
| Qualify-refs trigger | Both auto (after reverse) and manual CLI | Zero-config default + manual re-run/dry-run inspection |
| Qualify-refs ambiguous names | Skip + log | Tool can't guess schema; user must resolve manually |
| Qualify-refs error policy | Swallow in reverse-engineer | Post-processor is best-effort; never fails reverse-engineer |
| Extension ownership filter | `NOT EXISTS pg_depend.deptype='e'` | Standard PostgreSQL mechanism; robust across PG versions |
| Function-call edges | Destination-type check (not context) | Functions are called in any SQL context; type check is more reliable than parsing context |
| Disconnected vertices | Type priority dominates | Ensures sequence→table ordering even without explicit edges |
| Database settings | Properties (encoding/locale/template) → create_database args; ALTER DATABASE SET → single SQL file | Properties apply at DB creation; SET params are independent scripts |
| Extension version | Not pinned in DDL (informational in autodoc) | Pinning fails on clusters with different package versions |
